## Как воспроизвести

* **SQL:** `cd docker && docker compose up -d --build`, затем `docker exec -it oracle-test /opt/solution/scripts/run_sql.sh all`. Подробности — в `docker/README.md`.
* **Python:** `python C_Python/nedoimka.py` (нужны pandas ≥ 1.5; CSV берутся из `data/`).
* **Excel:** откройте `B_Excel/nedoimka_analiz.xlsx`; чтобы обновить запросы на своей машине, укажите путь к папке с CSV в параметре `DataFolder`.

## Главные «грабли» данных и как они обойдены

* **Дубли.** Одна запись (`id`) выгружена дважды, иногда в другом формате суммы (`976769,45` и `976 769,45`). Дедупликация идёт по `id` после нормализации; по «сырому» тексту строки нашлась бы только часть дублей.
* **Пробелы в КБК** (77 строк): без `TRIM` 77 строк начислений не нашли бы КБК в справочнике.
* **Пустые суммы** поступлений (50): трактуются как 0, NULL в SQL обёрнут в NVL.
* **NULL в excluded_kbk:** `NOT IN` возвращает пустой результат — заменён на `NOT EXISTS`.
* **ИНН без поступлений** (10, в том числе крупнейшие должники): нужен внешний join агрегатов.
* **Fan-out** при соединении строк начислений и поступлений: сначала агрегация, потом join.
* **Регионы** с лишними пробелами и в ВЕРХНЕМ РЕГИСТРЕ — нормализуются.
